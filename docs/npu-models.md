# Моделі для npu-llm (OpenVINO, Intel NPU)

Цей документ описує готові моделі з організації [OpenVINO на Hugging Face](https://huggingface.co/OpenVINO), які можна використати в проєкті `npu-llm` без власного експорту, та як їх додати.

## Чому не всі моделі підходять

Intel NPU (у тому числі Intel AI Boost на Core Ultra 7 265H) працює з OpenVINO найкраще з моделями у форматі **int4** і розміром до приблизно 8B параметрів. Великі моделі (27B і більше) або fp16-версії можуть:
- не запускатися через обмеження NPU на розмір графа;
- працювати дуже повільно або не вміститися в пам'ять NPU.

Тому для першого запуску рекомендую брати `int4` версії моделей 3B–8B.

Shared memory 17.9 ГБ у Task Manager означає лише ліміт системної RAM, яку може використовувати NPU, а не окрему пам'ять NPU. Це не обмеження розміру моделі.

## Рекомендовані моделі

### Текстові моделі (для чату)

| Модель на Hugging Face | Параметри | Формат | Опис | Рекомендація |
|---|---|---|---|---|
| `OpenVINO/LFM2.5-8B-A1B-int4-ov` | 8B (MoE, ~1B активних) | int4 | Компактна MoE-модель: велика ємність, але мало активних параметрів, тому швидка на пристроях із обмеженими ресурсами. | Спробувати після базового тесту |
| `OpenVINO/Qwen3-VL-4B-Instruct-int4-ov` | 4B | int4 | Мультимодальна (текст + зображення) модель Qwen3-VL. Для чисто текстового чату теж працює, але код має вміти приймати зображення. | Якщо потрібен аналіз картинок |
| `OpenVINO/Qwen3-VL-8B-Instruct-fp16-ov` | 8B | fp16 | Більша версія Qwen3-VL. fp16 важчий за int4, на NPU може бути повільним. | Не рекомендовано для першого запуску |

### Мультимодальні моделі (текст + зображення)

| Модель на Hugging Face | Параметри | Формат | Опис |
|---|---|---|---|
| `OpenVINO/Phi-3.5-vision-instruct-int4-ov` | ~4B | int4 | Vision-модель від Microsoft, добре працює з описом зображень. |
| `OpenVINO/InternVL2-1B-int4-ov` | 1B | int4 | Дуже легка vision-модель, підходить для тесту. |

### Великі моделі (поки не рекомендую для NPU)

| Модель на Hugging Face | Причина |
|---|---|
| `OpenVINO/Qwen3.8-27B-int4-ov` | 27B. Велика, швидше за все не запуститься або буде дуже повільною на NPU. Краще використовувати на GPU або CPU. |
| `OpenVINO/Muse-Glimmer-30B-int4-ov` | 30B, те саме обмеження. |
| `OpenVINO/llava-v1.6-mistral-7b-hf-int4-ov` | Vision-модель 7B, потенційно можлива, але старіша і важча за Qwen3-VL-4B. |

> Порада: назви та наявність моделей на HF змінюються. Перед завантаженням відкрий сторінку моделі й переглянь розділ "Files" та "Model card".

## Як завантажити модель

Модель з організації OpenVINO вже в форматі OpenVINO, експорт через `optimum-cli` не потрібен.

### Варіант 1: через CLI

```bash
uvx --from huggingface_hub hf download OpenVINO/Qwen3-VL-4B-Instruct-int4-ov --local-dir models/qwen3-vl-4b-int4
```

### Варіант 2: через Python

```python
from huggingface_hub import snapshot_download

snapshot_download(
    repo_id="OpenVINO/Qwen3-VL-4B-Instruct-int4-ov",
    local_dir="models/qwen3-vl-4b-int4",
)
```

Після завантаження в папці мають бути файли `openvino_model.xml`, `openvino_model.bin` та токенізатор (`tokenizer.json` тощо).

## Як додати модель до проєкту

1. **Завантаж модель** у папку `models/` (див. вище). Папка `models/` уже використовується в README, тому тут все буде на своєму місці.

2. **Знайди, де задано шлях до моделі.** У коді проєкту шлях зараз вказує на `models/qwen_npu_sym`. Пошук у репозиторії:
   ```bash
   grep -rn "qwen_npu_sym" .
   ```
   Найпростіше змінити шлях у змінній конфігурації або в `.env` (шаблон є в `.env.example`).

3. **Оновити шлях** на нову папку, наприклад:
   ```
   MODEL_PATH=models/qwen3-vl-4b-int4
   ```
   Якщо змінної немає, заміни рядок, де створюється `LLMPipeline`, на нову папку.

4. **Запусти застосунок:**
   ```bash
   uv run npu-llm
   ```

5. **Якщо модель не запускається на NPU**, перевір:
   - чи встановлений драйвер Intel NPU (версія `32.0.100.5540` з твого скріна підходить для Core Ultra);
   - список доступних пристроїв:
     ```python
     import openvino as ov
     print(ov.Core().available_devices)
     ```
     Має з'явитися `NPU`;
   - чи не перевищує довжина промпту ліміт NPU. Для NPU часто потрібно задати максимальну довжину промпту в конфігурації пайплайна.
